- [x] **P8.3** `ShapeGenerator` procedural meshes. — `IN REVIEW`

  `../primewatch2/src/gl/ShapeGenerator.hpp:8-15`. Behavioural spec: six free functions that each
  build a `Vec<Vert>` (CPU-side, no GPU) of procedural geometry — cube tris, cube-from-center,

  8. [x] `pub fn generate_camera_line_segments(perspective: Mat4, transform: Mat4, center_line_length: f32)

  **Watch for:**
  - glam `Mat4 * Vec4` is the matrix-vector product (column-major, same as glm) — use `.extend(1.0)` /
    `.truncate()` for the vec3↔vec4 hops, not `Vec4::from`.
  - `Quat * Vec3` in glam rotates the vector (matches `glm::quat * vec3`); `q1 * q2` composition order
    matches glm (Hamilton, `(q1*q2)*v == q1*(q2*v)`).
  - Integer loop counters are C++ `int`; `bottom_latitude_line` must be `i32` (can be used as an
    inclusive upper bound `<=`).
  - No GPU/wgpu here — pure CPU vertex generation, mirrors `gl::immediate` being CPU-only. All symbols
    dead until P8.4 (expected dead-code warnings, no `#[allow]`).
  - Keep every verbatim C++ quirk (the `normal={0,0,-1}` on all cube lines, the dead
    `latitudeLine==0` branch behaviour, the non-`center`-offset truncated-sphere apex).
