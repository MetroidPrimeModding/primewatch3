- [x] **P4.5** Introduce `Ctx<'a> { structs: &GameStructs, mem: &GameMemory }` and thread it. — `DONE`

  Not a C++ port — this is the "explicit context, no globals" convention from
  `RUST_CONVERSION.md` / `CLAUDE.md`. The C++ side reaches `GameMemory` and the defs registry as
  ambient globals; Rust bundles the two borrows into one `Ctx` passed by reference.

  **Decision (orchestrator) — layer split:**
  - **Live-handle layer (`GameInstance`)** takes `&Ctx` — every method that either reads memory or
    walks the struct graph on a live address.
  - **Definitions layer (`GameStruct` / `GameMember` / `GameEnum` / `GameStructs`)** keeps its
    `&GameStructs` params. These are pure graph queries over the loaded schema; they have no
    business borrowing `GameMemory`. `Ctx` bundles what a *live traversal* needs, not what a
    definition lookup needs. `GameInstance` methods pass `ctx.structs` down into this layer.

  **Steps:**
  - [x] 1. New module `src/ctx.rs` (top-level: it glues `structs::` + `mem::`; `mod ctx;` in `main.rs`).
     ```rust
     #[derive(Clone, Copy)]
     pub struct Ctx<'a> {
       pub structs: &'a GameStructs,
       pub mem: &'a GameMemory,
     }
     impl<'a> Ctx<'a> {
       pub fn new(structs: &'a GameStructs, mem: &'a GameMemory) -> Self { ... }
     }
     ```
  - [x] 2. `src/structs/prime_structs.rs` — change these `GameInstance` methods to take `ctx: &Ctx` in
     place of their current `game_structs` / `mem` params (drop the individual borrows):
     `get_type`, `get_member`, `member`, `element_size`, `element`,
     `read_u8/u16/u32/u64/f32/f64/bool/string`. Bodies use `ctx.structs` / `ctx.mem`. Internal
     calls into the defs layer become `struct_.get_member_by_name(ctx.structs, name)` etc.
  - [x] 3. Leave unchanged: `GameStruct::{get_member_by_name, extends}`, `GameMember::get_type`,
     `GameEnum::*`, `GameStructs::*`, and `GameInstance::{new, with_bitfield, with_member}` ctors
     (the ctors take raw data, no context). `globals.rs` `get_state_manager` / `get_main` stay
     context-free (they only construct a root `GameInstance::new`).
  - [x] 4. Add the P4.4-flagged ergonomic chain helper on `Ctx` (or `GameInstance` taking `&Ctx`) —
     whichever reads cleaner. Minimum: a `GameInstance::get(&self, ctx, name)` alias is **not**
     needed; the win is that `a.member(ctx, "b").member(ctx, "c").read_u32(ctx)` now threads one
     arg. If a `Ctx` method like `ctx.instance(addr, type)` or a chain builder is trivial, add it;
     otherwise just leave the `// P4.5:` comment resolved to "one-arg threading achieved via `&Ctx`".
     Don't over-build — no macro, no builder struct unless it's <15 lines.
  - [x] 5. Update the `#[cfg(test)] mod tests` in `prime_structs.rs`: build `let ctx = Ctx::new(&structs,
     &mem);` (tests that only need structs can pass a `GameMemory::new()` empty snapshot) and pass
     `&ctx`. Keep every existing assertion.
  - [x] 6. `src/mem/area_utils.rs` stays commented out — P6.2 rewrites it. Do **not** update the dead
     pseudocode.
