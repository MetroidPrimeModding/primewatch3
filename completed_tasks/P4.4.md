  **Decision (orchestrator): do NOT implement `std::ops::Index`.** `Index::index` is
  `&self -> &Output` with no extra params. Member resolution needs `&GameMemory` (pointer
  auto-deref) and yields an **owned** `GameInstance` (fresh address/type), so it fits neither the
  arg list nor the reference return. Faking it (interior mutability / leaking a box / a memory-less
  half-version) would diverge from the C++ `operator[]` contract this task exists to preserve.
  Instead add a panicking method mirroring C++ `GameMember::operator[]` exactly, and keep
  `get_member` as the `Option` form. The ergonomic `x["a"]["b"]` chain is recovered in P4.5 via a
  `Ctx`-based helper (single context arg) — note that forward-dependency.
