  ### Watch for
  - **Float format specifiers:** C++ `{:0.3f}` → Rust `{v:.3}`; `{:0.8f}` → `{v:.8}`; `{:0.2f}` →
    `{v:.2}` (transform/matrix rows). No `f` suffix, no `0` flag needed (Rust pads to precision).
  - **Reads default at the callsite** (P7.1 contract): `ctx.mem.read_f32(addr).unwrap_or(0.0)`,
    `.read_u32(..).unwrap_or(0)`. Do **not** add defaulting to `GameMemory` / `GameInstance`.
  - `object_tag_to_string` lives in `game_object_utils.rs`, not `inspector.rs` — matches the C++
    module split and keeps it available to P8 `WorldRenderer` without an `inspector` dep. It needs
    `use crate::structs::prime_structs::GameInstance;` (already imported there).
  - Dispatch precedence: special table beats `rstl::vector<` prefix and enum/struct — same order as
    C++ `render` (`:49-60`). The existing `PRIMITIVE_TYPES` check stays first (C++ has primitives in
    `specialRenderers` too, but they resolve identically either way).
  - `CTransform` cell arithmetic `(c*4 + r)*4` with `c in 0..3, r in 0..4` reaches byte offset 44
    (`posZ`), +4 = 48 = `CTransform` size. Port the arithmetic literally; don't "fix" it to a
    3×3 + translation split.
  - `four_cc_to_string` can produce non-printable bytes in the `String`. C++ writes them raw into a
    `std::string`; Rust `char::from(u8)` is the faithful equivalent (Latin-1 mapping for 0x80-0xFF).
    Don't sanitize — a caller wanting a clean display is P9's problem, and the game's tags are ASCII.
  - Still **no call site** (Phase 9). `Inspector` / its methods stay dead-code-warned; don't add a
    speculative `app.rs` call, don't `#[allow]` unless clippy `--all-targets` fails.
